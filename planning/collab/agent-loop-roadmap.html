attn · agent loop, v8 james · july 2026

Agents speak in your margin. In theirs, they whisper to you.

Commenting on someone's doc is a social act — your name on a mark means you vouch. An agent's advantage points the other way: it doesn't have the author's context, it has yours. So agents are full participants on your own docs, and on received docs they become a private reading aid — briefing you in a margin only you can see, through your membership, on your machine. No remote agent principals exist anywhere.

YOUR DOCS

Agents read, comment, reply, edit — full participants with the ⊳ chip. The kernel loop: "address my attn comments."

RECEIVED DOCS

Agents read through your membership and brief you in a private margin — never transmitted. Only humans speak publicly.

UNATTENDED TEAM AGENTS

CI reviewers, collaborators' bots — parked. A different product for a different customer; tokens and remote protocol wait for a named use case.

The trunk — humans read and speak here; everything else is a branch
WHY THE HUMAN MARGIN COMES FIRST

One margin, three consumers

Every agent feature on this page is secretly a human-margin feature. Copy-my-marks is only worth pressing if leaving marks is effortless — the select→comment gesture is the input device of the whole agent loop. Paste-notes renders into the same cards humans read. The private layer is the same components with a dashed border.

Public human comments · the agent's private layer · unsent drafts — same anchors, same cards, same threads. The human consumer justifies the system even if no agent ever shows up.

The Docs-familiar interface is also the growth loop: a colleague on a phone reviews with zero onboarding because the UI is already in their fingers. An "agent-native" review UI would break the one loop that brings new humans in.

WHAT "DOCS-GRADE" MEANS — ACCEPTANCE CRITERIA

Reading comments like it's 2010

Continuous workstream, not a gap row — every item below is judged against "would a Google Docs user need this explained?"

  • select text → comment in one gesture, mouse or keyboard
  • highlight in text ↔ card in margin — click either, both light up
  • threads: reply, resolve, reopen; resolved collapse out of the way
  • unresolved counter with next / prev navigation
  • suggestion slips the owner accepts / rejects inline
  • reader mode that stays beautiful on a phone — the recipient's view

Warm surface for humans, sharp behavior for agents — in that order.

The rule — when your agent edits, and when it marks
DIRECT EDIT · decisions already made

Execution goes in the file

On your own docs the agent already holds write — use it. Wrapping mechanical work in suggestion slips is ceremony: you'd accept them all anyway, and git diff + the file watcher are the audit trail.

  • typos, formatting, link fixes, structure cleanup
  • "apply what we agreed" — executing a decision you already made
  • "rewrite section 2 the way I said" — instructed changes
  • anything you'd rubber-stamp: don't make yourself a merge bottleneck

Edits execute decisions already made.

THE MARGIN · decisions still yours

Judgment waits in the margin

The margin is a queue of pending human judgment — never an agent output channel. Four marks earn their place:

  • open questions — "this date contradicts the client email"; an edit would silently pick an answer that isn't the agent's to pick
  • pre-read triage — marks on a doc you haven't read yet: "the real decision is here." You open attn and the margin is your agenda
  • voice-sensitive slips — launch copy, external memos: suggestions you cherry-pick one at a time, keeping your voice
  • thread-closing replies — "done, cut the compat section — r7": verify per-thread instead of re-reading the doc

Comments surface decisions still yours to make; marks aim your next reading pass.

The prompt convention falls straight out: edit what you're sure of and what's mechanical · comment what needs my judgment · reply in-thread when you've addressed a mark — confidence does the routing. This is why agent→margin writing stays narrow on your own docs (replies, questions, triage, opt-in slips) while its main home is the received-doc private margin.

4
Agent · on your machine

Reads the doc through your daemon (already decrypted, because you're a member) and reads your repo. Writes anchored notes into your private margin — a local room overlaid on her doc, never transmitted.

5
You · in attn

Read Maya's doc with the briefing pinned paragraph by paragraph — highlights where it touches your world, conflicts called out with file:line receipts.

6
You · publicly

Where you want to speak, you comment — your words, your signature. Or promote an agent draft you've edited; posting is a deliberate human act. Maya sees only you.

The E2E story stays airtight: content decrypts only on your machine, and your agent reads it there — the same trust domain as your own eyes. Nothing about the agent touches the relay.

The bridge — one copy from the web share, no CLI, no install

"Copy prompt for your agent"

A button in the browser share view. The browser already holds the decrypted document — so the prompt carries the content inline, and one paste into Claude Code or Codex delivers the whole "give me a read on this against my project" flow with zero attn dependency. This is agentation's copy-paste tier, applied to docs — and it ships as a frontend-only change, before any of the kernel exists.

It's also the conversion path: the prompt's last line teaches the agent (and its owner) that the upgraded experience exists. The web stays the human surface — this button is the handoff point where a received doc meets your local context.

TIER 0 · today, nothing installed

Briefing in chat

Agent reads the inline doc + your repo (it's in cwd), answers with a quote-anchored briefing: the ask, what touches your work with file:line receipts, what to push back on.

TIER 1 · attn + mcp installed

Briefing in the margin

Same prompt — the agent detects the attn_* tools and writes the briefing as private-margin notes instead of chat. The paste doesn't change; the destination upgrades.

Key hygiene: content travels inline, so the #key fragment never enters the transcript — the prompt cites the share by its bare URL. Consistent with the bearer-leak concern: agent transcripts are the leakiest channel there is.

What this does to the product — native is the power tool, web is the reach
NATIVE · where your agents live

The daemon is the agent hub

The native app stops being "a nicer viewer" and becomes the thing the browser can't be: the place where your files, your memberships, and your agents share one trust domain.

  • machine-scope MCP: every session, every project, one registration
  • local rooms: mark up anything, shared or not
  • private margins on received docs — your context, applied by your agent
  • the repo is right there: briefings come with file:line receipts

You install attn because of what your agents can do with it.

WEB · where other humans meet your doc

The share stays human-simple

The browser build keeps exactly one job and stays great at it: zero-install reading and human review. No agent surface to secure, no tokens to leak — a link someone can open on a phone in Slack and immediately comment on.

  • view / comment / suggest links, unchanged
  • great on phones — the coffee-shop reviewer is a human
  • "Copy prompt for your agent" — the one-paste bridge to Claude/Codex
  • every link sent is a product tour that ends at the native install

You send a share because any human can open it.

Deliberately not building

The remote agent surface didn't get smaller — it got deleted. The agent piggybacks your membership locally, so no remote agent principal exists to credential, transport, or verdict.

Agent tokens & agent ShareTransport

No remote principal, nothing to tokenize. Returns only if an unattended team agent gets a named use case — and the trigger will be bearer-leak risk, not tiering.

Remote write / local "edit tier"

No doc-remote principal ever writes — the owner's daemon is the sole writer; accept is the only write path. Locally, the OS already granted write; REMAP already keeps marks alive across edits.

Agents speaking on others' docs

Public marks carry a human signature or they carry nothing. Agent drafts exist — but posting is a deliberate human act, every time.

Order of work

  1. 00 copy-prompt bridge (received docs, web) — frontend-only, ships first; works with nothing installed.
  2. 01 local rooms — the one non-UI piece: marks on any doc, bindable to joined docs (= the private margin).
  3. 02 copy-marks + 03 paste-notes — the loop closes, both directions, both surfaces. This is v1 complete: three buttons and a room.
  4. 04 attn mcp — gated on the clipboard loop proving daily use; same formats, minus the manual steps, plus liveness.

v1 has no MCP, no CLI verbs, no protocol changes, no new trust surface — and because the clipboard is just text, the loop works identically on browser-authored and native docs, both directions: the "works on both" requirement is met at tier 0 for free. What v1 gives up is only liveness (marks streaming in while you watch) — that's the launch-video magic, not the daily value, and it arrives with MCP once the habit is proven. And none of this is a pivot away from human review: the Docs-grade margin is the trunk, worked continuously — every agent feature above renders through the same components humans read and write with.
